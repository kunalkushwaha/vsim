vsim · use-case deck

One 3D scene in code.
Every video it implies.

vsim renders deterministic 3D video from TypeScript — the same scene plays live in a browser, exports to MP4 on a server with no GPU, and fans out into thousands of personalized variants that are byte-for-byte reproducible.

scene.ts→ deterministic runtime→ live embed+ MP4+ N variants
the mechanism

Four engine properties, four business properties

Deterministic

Personalization at scale

Fixed timestep, frame-indexed time, seeded RNG. Render a template 10,000 times with 10,000 data payloads — every output is exact, auditable, cacheable.

One document

Video and embed from one source

Timeline UI, code, and AI all read/write the same scene document. The landing-page hero and the ad are the same file.

Pure-TS renderer

Renders anywhere

The draft renderer needs no GPU: per-pixel PBR, shadows, fog, anti-aliasing — in TypeScript. CI boxes, lambdas, and browsers are render farms.

Code-first

Video enters CI/CD

Scenes are diffable files with golden-frame tests. Videos re-render on merge, like any other build artifact.

use case · personalization

10,000 videos, one scene

Year-in-review recaps, sales outreach with the prospect's name in true 3D type, order-confirmation clips, fantasy-league highlights. Template once — render per user. Determinism means variant #7,214 is provably the template plus that user's data, nothing else.

// the whole personalization pipeline
for (const user of users) {
  await renderToVideo(recapScene(user), { output: `out/${user.id}.mp4` });
}  // same pixels on every machine, every run — cache by data hash

Docs & devrel

use case · data-driven video

Video as a nightly build

Market recaps, sports scores, weather, dashboards-turned-shorts. A cron job pulls the day's data, feeds the template, renders on a plain CPU box, publishes. No GPU fleet, no render surprise at 3 a.m. — preview equals final, always.

cron / CI→ data JSON→ scene template→ vsim render→ MP4 → socials
Why deterministic matters here

Automated pipelines can't have flaky output. Byte-identical renders make video diffable, cacheable, and safe to publish unreviewed.

Why pure-TS matters here

The renderer runs where the data already lives — a lambda, a GitHub Action, a worker — with zero native dependencies except ffmpeg for muxing.

use case · creators & social

A character studio in a code editor

A bundled cast — rigged humans with real skin textures, a fox, a quadruped, an original cartoon mouse — with walk/run/idle/wave clips, morph-target lip-sync driven by audio beats, and one-flag manga styling. Templates become channels.

Music

Beats are frame indices in the document: pulse, cut, and lip-sync lock to audio reproducibly.

Shorts pipelines

One story template + a script file per episode. Character motion blends from pose to clip (blendInFrames) — no snapping.

Styles

style:"manga" flips the same scene to cel shading + outlines — anime and realistic content from one asset base.

use case · ai-native video

The controllable alternative to gen-video

The AI copilot turns prompts into schema-constrained edits of the scene document — it cannot emit invalid geometry, and it never touches the render loop. Agents get what diffusion can't give them: a video target they can hit exactly, verify, and iterate on.

$ vsim edit scene.ts --prompt "make the cube blue, add a point light" --render out.mp4
# prompt → validated document ops → deterministic render — reviewable at every step
For agent builders

LLMs author scenes as code/JSON; goldens verify the result. Video generation becomes a test-driven loop instead of a slot machine.

roadmap · docs/plan-realism-roadmap.md

The path to realistic

R1 · renderer polish

Bilinear-PCF soft shadows, opt-in ACES tone mapping, perspective-correct UVs, mipmaps, transparency, point-light shadows.

R2 · atmosphere

Sun disc + horizon glow, hemisphere IBL bounce, deterministic particles, grass scatter on the hashed-variation system.

R3 · characters

Clip-to-clip crossfade, PBR-mapped human exports, foot-lock IK, spring-bone secondary motion, facial/viseme library.

R4 · photoreal finals

Blender/Cycles backend for path-traced MP4s (bake script already runs through the same runtime); browser path tracer for zero-server stills.

R5 · web & scale

Fetch asset loading, WebCodecs in-browser export, worker-tiled rendering, WebGPU preview.

Sequencing

Crossfade first (motion quality is the visible gap), then cheap renderer wins, then assets, atmosphere, web, photoreal.
